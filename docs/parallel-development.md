# 并行开发的知识边界

配置格式 5 把原文登记拆成 `.codestable/documents/<编号>.json`，本机位置单独放到
被忽略的 `.codestable/local.json`，或通过 `--repository` 提供。配置和登记只保存范围、
状态及来源，正文始终留在原文件。旧配置明确报告需要调整，不自动迁移、重建或删除知识。

独立任务在各自检出目录中分别新增任务记录和必要的独立经验；生成目录和统计留在
本地缓存。同一逻辑任务由当前负责人汇总，协作者提供证据。复用知识不改无关卡片，
相同任务版本竞争明确失败，不能用后写覆盖先写。

`learn` 确認同一请求已完整应用且没有待恢复事务时，只读返回原任务编号，不创建锁、
记录或新版本。未完成请求仍核对计划、目标版本与证据，保留原有锁、日志恢复及回滚。
`receipt-check` 只读核对原简报的查询范围与相关来源；无关任务记录和缓存变化不会
使它失效，相关原文变更、删除或新增适用知识则需要复核。

MATT 仍提供开发方法，CS 仍独立管理知识。普通任务结束完成知识处置；环境复盘和
CS 表现分析按需调用，不加入固定收尾。细则由[开发方法与知识归属](../skills/cs/references/development-methods.md)
与[原文登记说明](../skills/cs/references/documents.md)维护，不增加方法专用知识协议。

## 本次验证

2026-10-10，Python 3.13.14：171 项单元测试、15 项发行检查、生成脚本一致性和两个 CS
技能格式校验通过。源码身份及双仓组合结果见[机器记录](parallel-validation.json)。
新增测试实际启动两个进程竞争同一任务版本，检查已完成重试零写入、中断恢复、工作区/
暂存区/提交登记读取、路径越界、相关知识变化和旧配置零写入拒绝。

team-workflow 的 8 项真实接口和 8 项并行组合检查通过。两个分支分别新增原文登记、
任务记录与独立经验，实际合并无人工冲突处理，全部可以检索。另两位独立代理完成
不同开发任务并各自提交，合并后 14 项业务测试通过；没有修改共享配置、自动调用分析
或复制原文。代理认为原文已覆盖本次结论，未额外建卡。第三位代理验证三个前提缺失
场景，均停止方法调用且文件摘要不变。

平台并行和响应丢失由本地可控服务验证，没有发布真实 Issue 评论。本轮不代替两位
真实团队成员试点，不扩展为新业务验收。仅定点调整本仓配置、模板和测试夹具；消费项目
的原文、卡片及历史记录不作批量处理。
